AI-Sentinel

Intelligent Security Analysis of AI-Generated Software

AI coding assistants make development faster, but the code they generate is not automatically secure. It may hide SQL injection, XSS, hardcoded credentials, command injection, insecure authentication, and improper input validation. AI-Sentinel analyzes that code, understands its context, and prioritizes what to fix first.

    Vulnerabilities detected
    

    From slide 11. This build also checks eval/exec, pickle/YAML, SSRF, insecure random, debug mode, and routes without a login check.
    

    

    SQL Injection
    Input built into a query. Fix: parameterized queries / prepared statements.
    

    Cross-Site Scripting (XSS)
    User input rendered as HTML without escaping.
    

    Hardcoded Credentials
    Secrets written in code. Fix: environment variables, never commit them.
    

    Command Injection
    Input reaching a shell command.
    

    Path Traversal
    Input used as a file path, with ../ to escape the folder.
    

    Weak Cryptography
    MD5 / SHA1 for security use, instead of strong hashing.
    

    Insecure Authentication
    Sensitive routes with no login check.
    

    Improper Input Validation
    Untrusted input reaching a dangerous operation unchecked.
    

    

    Example mitigation from the presentation: use parameterized queries or prepared statements for SQL queries.
    

    


    

    Risk prioritization
    

    Risk factors from slide 12: vulnerability severity, exploitability, exposure, data sensitivity, application context, and existing security controls. The exact level depends on the surrounding application — that is why the same SQL injection can be High in one context and Critical on a public route with no auth.
    

    

    Critical
    Fix first. Reachable, public, and sensitive — for example SQL injection on a public login route.
    

    High
    Fix soon. Serious flaw, or a critical pattern in a less exposed context.
    

    Medium
    Fix in the next pass. Real weakness, lower exposure or impact.
    

    Low
    Fix when convenient. Best-practice issue, or not reachable from user input here.
    

    

    Presentation example: SQL Injection → CWE-89 → High risk → use parameterized queries / prepared statements. In this tool, that same finding moves up or down with taint flow, route exposure, and sensitive data.
    

    


    

    Why context matters
    

    

    Traditional tools
    Examine code without executing it, may produce false positives, and have limited understanding of application context.
    

    Manual review
    Depends on security experts and is time-consuming for large projects.
    

    AI-Sentinel
    Looks at code structure, data flow, input sources, surrounding functions, and sensitive operations before ranking.
    

    

    Honest limit, from the presentation: a prototype cannot guarantee software is completely secure, detection can have false positives or false negatives, and human security review may still be required for high-risk applications. A clean scan here means none of the checked patterns matched, not that the code is perfectly secure.
    

    Built with Python, Flask, HTML, CSS and JavaScript, and Python AST — following the presentation's architecture. Future work from the presentation: more languages, real-time IDE integration, GitHub/GitLab and CI/CD integration, and improved data-flow analysis.
